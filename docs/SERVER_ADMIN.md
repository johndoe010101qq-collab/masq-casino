## Возможности

- Общие профили RTP 50–95%, шаг 1%; лимиты ставок и настройки показа.
- Серверная проверка подписанного профиля SPWorlds и отдельный список ID владельцев MASQ. Никнейм и поле `isAdmin` платформы прав не дают.
- Сеанс входа на 15 минут, случайный Bearer token только в памяти клиента; сервер хранит хеш в памяти. Перезапуск сервера завершает сеансы, настройки и аудит остаются в базе. Токен не попадает в ссылку, localStorage или журналы.
- Сохранение полного набора настроек одной транзакцией с проверкой версии. При конфликте изменений нужна новая версия, чужая правка не перезаписывается.
- Журнал автора, времени, причины, предыдущей и новой версии. Настройки не позволяют назначать индивидуальные шансы или рисовать баланс.
- `/admin` открывает страницу входа. Панель с настройками появляется только после подтверждения сервером прав аккаунта.

**Сохранённый профиль пока не включён в денежные игры.** Текущий `HallSession` ведёт демонстрационные игры в браузере; сервер управления не меняет его баланс и результаты. `/api/config` явно сообщает `gameplayMode: browser-demo` и `currencyMode: unavailable`. Удаление надписи «демо» не включает реальные АР.

## Локальный запуск

Нужен Node.js 24. SQLite используется через встроенный `node:sqlite` (экспериментальный API Node). После клонирования скопировать [.env.example](../.env.example) в `.env.local`: шаблон содержит публичный App ID и адреса локального запуска, а секретные поля пустые. Для подключения серверной панели в локальном клиенте установить `VITE_MASQ_SERVER_ADMIN=1`. Секреты добавляются владельцем в локальный файл или секрет-хранилище сервера; env-файл, SQLite и её служебные файлы исключены из Git.

Серверу нужны:

| Настройка | Назначение |
| --- | --- |
| `SPW_APP_TOKEN` | Серверный токен именно этого мини-приложения; никогда `VITE_*` |
| `MASQ_OWNER_ACCOUNT_IDS` | Точные `accountId` владельцев, через запятую; не ники |
| `SPW_TIMESTAMP_UNIT` | `seconds` или `milliseconds` **после подтверждения формата площадкой** |
| `MASQ_APP_ORIGIN` | Единственный разрешённый origin клиента; локально `http://127.0.0.1:5178` |
| `MASQ_ADMIN_DB` | Путь к SQLite; локально `server/data/masq-admin.sqlite` |
| `MASQ_ADMIN_PORT` | Локально `5187` |

В отдельных терминалах из корня проекта:

```text
npm run admin:server
npm run dev -- --host 127.0.0.1 --port 5178 --strictPort
```

Vite передаёт `/api/*` на сервер `127.0.0.1:5187`; для браузера запросы остаются того же origin. Ссылка на страницу входа: `http://127.0.0.1:5178/admin`. Вход требует открытия приложения внутри SPWorlds; отдельная браузерная ссылка не заменяет подписанный профиль. Нельзя включать обход входа для внешней страницы.

Пока отсутствуют токен, ID владельца или подтверждённая единица времени, вход закрыт с `AUTH_UNCONFIGURED`. Единицы времени и обновление подписи не указаны в проверенных [типах SDK](https://github.com/sp-worlds/spwmini/blob/master/src/types.ts), а [middleware](https://github.com/sp-worlds/spwmini/blob/master/src/middleware.ts) проверяет только HMAC. Сервер требует свежую подпись, не старше 5 минут, и допускает до 30 секунд расхождения часов.

## Подключение к хостингу и настоящим АР

Этот сервер использует Node и файловую SQLite; статическая загрузка в Cloudflare Pages его не запускает. Для размещения нужен отдельно согласованный Node-хост с постоянным диском и маршрутизацией API на том же origin, либо отдельная реализация Workers/D1. Секреты настраиваются приватно на сервере, вне чата и репозитория. Настройки, база и аудит должны резервироваться.

Пример маршрутизации Node-хоста: `deploy/nginx-admin.conf.example`. Это шаблон, не запущенный хостинг. В production клиент собирается с публичным App ID и `VITE_MASQ_SERVER_ADMIN=1`; сервер получает тот же origin в `MASQ_APP_ORIGIN`. SQLite и env-файл должны находиться вне публичного `dist`. Лимит запросов текущего сервера считается по адресу соединения: за одним proxy он общий, для публичного запуска потребуется отдельно настроенный лимит на доверенном proxy.

До включения настоящих АР остаются серверные игровые раунды и RNG, общий журнал денег и резерва, атомарное удержание ставки, восстановление раунда после разрыва связи, подписанные платежные уведомления, устранение дублей и очередь выводов. Браузерное событие оплаты не разрешает начислить деньги. Банк казино имеет отдельные реквизиты и токен карты; токен приложения их не заменяет.

Публичное API вывода не описывает идемпотентный повтор или поиск перевода по нашему ключу. При неопределённом сетевом ответе вывод должен перейти на сверку, а не повторяться автоматически.
